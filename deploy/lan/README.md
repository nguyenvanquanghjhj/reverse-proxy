# Three remote backend nodes (LAN, NOT open Internet)

1. On each node install JDK21 and the same built version of the repository, with identical schema and assets. Configure `SHOP_DB_URL` pointing to a reachable PostgreSQL instance (separate from the proxy), `SHOP_FILES_DIR` as the same actual shared storage across backend nodes, `PBL4_BACKEND_BIND_HOST=0.0.0.0`, and the same 64-character `PBL4_PROBE_TOKEN` as on the proxy node. Backends MUST have firewall rules allowing only the proxy host and trusted management hosts. Never place PostgreSQL or file management directly on the Internet.
2. Start each backend with `java -cp "target/classes;lib/*" com.example.backend.DemoBackendServer 9001 8 10` on Windows (`:` separator on Linux). Port numbers can be the same if the backends are on separate machines. If you use all three on one backend host, assign distinct ports.
3. On the proxy host generate config: `python deploy/lan/lan_config.py --proxy-bind 0.0.0.0 --backends 192.168.1.21:9001 192.168.1.22:9001 192.168.1.23:9001 --output config/lan.properties`. Replace with YOUR actual IPs; do not copy example IPs blindly.
4. Start proxy with `java -cp "target/classes;lib/*" com.example.proxy.Main config/lan.properties`. Set `PBL4_PROBE_TOKEN` on this host as well; status polling uses it. Start only after validating firewall and database access.
5. From a trusted machine, set `PBL4_PROBE_TOKEN` in the environment and use `lan_check.py --backends <three actual IP:PORT values>`; avoid writing secrets into command history. Measure with existing `scripts/lab.py` for loopback comparators; for true LAN measurements, supply a separate controlled workload generator located outside the proxy host and preserve raw data.

Security: The service is plain HTTP. Use an isolated LAN/VPN; configure TLS termination at a trusted edge if clients cross untrusted networks. Never let backend `/control`, `/down`, `/up` be remotely reachable; existing code keeps these loopback-only. The probe token only protects readiness/metrics and is not a general-purpose authentication protocol or TLS substitute. Remote DB credentials must be managed outside source control. Only one migration/seeding operator may write during initialization.
